# GCDWebServer — Fork Changes

This is a fork of [GCDWebServer](https://github.com/swisspol/GCDWebServer) by Pierre-Olivier Latour, which is archived and no longer maintained. The original library is used here as an embedded HTTP server for [ES Memory](https://github.com/apocryphx/ES-Memory).

This file documents all changes made relative to the archived upstream.

---

## Security Hardening (April 2026)

Six vulnerabilities were identified in a security audit and fixed. The server binds to `localhost` only, which reduces the external attack surface — but any local process can reach it, so defense in depth still applies.

---

### Fix 1 — Unbounded heap allocation from `Content-Length` (DoS)

**File:** `Requests/GCDWebServerDataRequest.m`  
**Severity:** Critical

`initWithCapacity:self.contentLength` allocated directly from the client-supplied `Content-Length` header value with no upper bound. A request with a header value of `9223372036854775807` would exhaust virtual memory and crash the host process.

**Changes:**
- `GCDWebServerConnection.m`: Added `kMaxRequestBodySize` (64 MB). Non-chunked requests whose `Content-Length` exceeds this limit are rejected with 413 before the body is read.
- `GCDWebServerDataRequest.m`: Capped `initWithCapacity:` hint to `MIN(contentLength, 256 KB)` as a secondary safeguard so pre-allocation is bounded even if the connection-layer check is somehow bypassed.

---

### Fix 2 — Stack overflow via variable-length array in chunked encoding parser

**File:** `Core/GCDWebServerConnection.m` — `_ScanHexNumber()`  
**Severity:** High

`_ScanHexNumber` allocated `char buffer[size + 1]` as a C99 VLA, where `size` was derived from attacker-controlled chunk header data. A malformed chunk header with no CRLF causes the receive buffer to grow without limit; when CRLF eventually appears after a large amount of data, the VLA overflows the thread stack.

**Changes:**
- Replaced `char buffer[size + 1]` with a fixed `char buffer[128]`.
- Added an early return of `NSNotFound` when `size > 64` (a valid chunk size header is never more than 16 hex digits plus optional extensions).

---

### Fix 3 — Unbounded header accumulation (DoS)

**File:** `Core/GCDWebServerConnection.m` — `readHeaders:withCompletionBlock:`  
**Severity:** High

`readHeaders:withCompletionBlock:` accumulated socket data indefinitely while waiting for the `\r\n\r\n` header terminator. A client that never sends the terminator could stream data forever, exhausting process memory.

**Changes:**
- Added `kMaxHeadersSize` (64 KB). If the accumulated header buffer exceeds this limit before the terminator is found, the connection is aborted immediately (`block(nil)`).

---

### Fix 4 — CRLF injection via `authenticationRealm` in `WWW-Authenticate` header

**File:** `Core/GCDWebServerConnection.m` — `preflightRequest:`  
**Severity:** High

The `authenticationRealm` option was embedded directly into both the Basic and Digest `WWW-Authenticate` response headers without sanitisation. A realm string containing `\r\n` would inject arbitrary headers into the serialised HTTP response (response splitting).

**Changes:**
- Added `_StripCRLF()` — strips all `\r` and `\n` characters from a string.
- Applied to `authenticationRealm` before embedding it in both the Basic and Digest `WWW-Authenticate` header values.

---

### Fix 5 — Static process-lifetime nonce and missing URI binding in Digest authentication

**File:** `Core/GCDWebServerConnection.m` — `+initialize`, `preflightRequest:`  
**Severity:** High

Two weaknesses in the Digest authentication implementation:

1. The nonce was a class-level static initialised once per process lifetime and never rotated. A captured `Authorization: Digest` header could be replayed indefinitely against any session.
2. The `uri` field in the `Authorization` header was used only for the HA2 hash computation and never validated against the actual request path, allowing a credential captured for one endpoint to be replayed against any other.

**Changes:**
- Moved `_digestAuthenticationNonce` from a file-static to an instance variable, generated lazily per-connection in `preflightRequest:`. Each connection receives a fresh nonce.
- Added URI path validation: after verifying the HMAC response, the `uri` field is parsed as a URL and its path component is compared against `request.path`. Mismatches are treated as unauthenticated.

---

### Fix 6 — Incomplete HTML escaping in error responses

**File:** `Responses/GCDWebServerErrorResponse.m` — `_EscapeHTMLString()`  
**Severity:** Medium

`_EscapeHTMLString` only escaped `"` → `&quot;`, leaving `<` and `>` unescaped in error response bodies. If error messages containing HTML were ever rendered in a `WKWebView`, this would be a stored XSS vector.

**Changes:**
- `_EscapeHTMLString` now escapes the full set in safe order: `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`.
